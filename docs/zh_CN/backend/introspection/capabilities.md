# 能力探针 (Capability Probes)

[数据库内省](../introspection.md) 所描述的内容，是向数据库提出的一组问题，而不是每个数据库都能回答其中每一个。问一个服务器回答不了的问题，代价不止是一次失败的调用：它耗掉调用方为那个答案写下的分支，也耗掉读者区分"没有可报告的东西"与"没有办法报告"的能力。因此每一族都在方言上有一个探针——一个返回 bool 的 `supports_*` 方法——调用方在付出任何东西之前先查它。

本页说明这些探针承诺了什么。它不说明任何具体连接回答了什么。

## 探针为什么存在

一个想要未使用索引报告的调用方有两个问题，不是一个：这台服务器能不能回答，以及这个回答要多少代价。第二个是方法自己的文档字符串的事。第一个是探针的事，它存在是为了让调用方在付出之前决定，而不是在失败之后。

答案必须是关于当前所连服务器的**事实**，而不是关于它所属产品的猜测。所以先让方言适配到服务器，再去问探针：`backend.introspect_and_adapt()` 读取版本，定下依赖版本的那些能力，然后这个问题才值得问。一个尚未适配的方言仍然可以回答它在没有握手时就知道的东西，而 `version_at_least()` 是这类检查必须使用的谓词——它从不抛异常，并且在版本尚未确认时回答 `False`，因为没有人确认过的能力就不算被声称。

### 关于服务器的回答，而不是关于库的回答

探针不是方言类上的静态特性开关。一个用 `version_at_least((3, 0, 0))` 把关的能力，对一台服务器这样回答，对同一产品的另一个版本那样回答；这是预期行为，因为探针是针对手里这条连接求值的。把答案缓存在类上，会让针对一台服务器写下的报告描述另一台。

## True 承诺了什么

`True` 意味着这个引擎会回答。它不意味着答案是这个形状，不意味着答案便宜，也不意味着结果类型声明的每一个字段都会被填上。探针只回答一个问题——这个问题能不能被问——其余的由方法、它的结果类型和它的文档字符串承担。

### 它不承诺答案的形状

每一个 `True` 都带着一项义务。`supports_runtime_stats()` 要求 `format_runtime_metrics_query_statement()` 能为这个方言渲染；`supports_unused_indexes_detection()` 要求 `format_unused_indexes_query_statement()` 能渲染；这一族其余探针同理。一个背后没有格式化方法的承诺不是能力，而是一个"下一次调用会被拒绝"的声明。

渲染出来的查询所返回的东西，比探针所承诺的更窄：至少是结果类型能携带的那些地址列，每一族自己的契约写在它的格式化方法被记录的地方。探针从不承诺字段，只承诺可用性。

### False 意味着不要问

`False` 是一个完整的回答，而不是一次失败。调用方由此得知不值得做任何尝试，于是心里有数地走回退路径。一个回答不了的后端必须回答 `False`，并在探针的文档字符串里说明为什么——这个问题本来需要什么，以及为什么那份材料不在。文档字符串是这个声明的证据；一个旁边没写理由的 `False`，是一句要让下一个读者凭信任接受的断言。

`False` 也不等于空结果。空列表说的是问题被问了、答案是什么都没有；`False` 说的是问题从未被问。把它们混为一谈的调用方，会对一台不保存计数器的服务器报告"没有未使用索引"，而这恰恰是运维最不能收到的那份报告。

### 未填的槽不等于未回答的能力

在一个答案内部，缺席与拒绝是两件不同的事实。一个槽是 `None`，意味着服务器回答了、但没有测量那个字段——一个未被跟踪的计数器，一个引擎不保存的数字。一个探针是 `False`，意味着根本没有产生答案。把前者读成后者，会丢掉已经取到的测量；把后者读成前者，会凭空造出没有人产生过的答案。探针是调用之前唯一能分清这两者的地方，这也是它要先被查的原因。

### 两种被打破的承诺

"探针既不能多声称、也不能少声称"这条规则之所以存在，是因为两种失败在调用点都是安静的。

多声称，是一个背后没有格式化方法的 `True`。调用方被告知"可以"，于是选定报告路径、调用方法，然后被拒绝：方言完全没有声明格式化方法时是 `UnsupportedFeatureError`，回答这次查找的只是协议桩而不是格式化方法时是 `ProtocolNotImplementedError`。异常本身不是伤害。伤害在于调用方已经写好并测试了一条它用不上的分支，而捕获这个拒绝的代码会悄悄偏好一个它本来不需要的回退。一个背后什么都没有、却留在 `True` 的探针，就是一句被打破的承诺。

少声称，是一个本该是 `True` 的 `False`。什么都不会抛，什么都不会记日志，也没有调用方会知道这个问题本来可以回答。这项能力不只是缺失，它是隐形的，于是每个消费方永远走回退路径。多声称在第一次调用时就被发现，而少声称没有人会发现——这就是规则的后半句比它看起来更重要的原因。

## 如何使用一个探针

先查探针，再调方法。整个约定就是这一句，值得写出来，是因为没有任何返回类型能强制执行它。

```python
unused = []
if backend.dialect.supports_unused_indexes_detection():
    unused = backend.introspector.list_unused_indexes()

for row in unused:
    print(row.schema, row.table_name, row.index_name)
```

这里的 `unused` 为空，是一个能回答的服务器给出的合法答案：当前窗口里没有索引未被使用。它与探针回答 `False` 不是同一个事实，而探针正是把两者在调用点分开的东西。

### 探针决定能不能问，文档字符串决定代价

一族的代价写在公开方法自己的文档字符串里，而不是写在探针里。`True` 说的是这个问题能被回答；它没说答案便宜，而把探针当成代价估计，会让昂贵的几族看起来免费。需要知道价钱的调用方，去读它正要调用的那个方法。

探针是方言方法，而不是内省器上的调用，所以它们在异步内省器上和同步内省器上是同一批；只有调用本身要用同样的名字 await。

```python
async def table_report(backend):
    if not backend.dialect.supports_table_stats():
        return []
    return await backend.introspector.list_table_usage_stats()
```

## 发现完整集合

探针声明在方言上，而不是收在一个注册表里，所以这个集合可以从对象本身读出来。协议声明了全部，这正是"对内省做内省"不必读源码就能成立的原因：向协议要它的 `supports_` 名字，然后拿每一个去问已经适配的方言。

```python
from rhosocial.activerecord.backend.dialect.protocols.introspect.introspection import (
    IntrospectionSupport,
)

probe_names = sorted(
    name for name in dir(IntrospectionSupport) if name.startswith("supports_")
)
answers = {name: getattr(backend.dialect, name)() for name in probe_names}

for name in probe_names:
    print(f"{name}: {answers[name]}")
```

这个循环返回的是声明，不是测量：它列出的是这个方言声称能回答的问题。声称是否被兑现，是另一项检验——调用那个方法——所以这个循环是一份支持度报告的起点，而不是它的证书。

> 哪些探针回答 `True` 因后端而异；每个后端自己的文档说明它自己的答案。
