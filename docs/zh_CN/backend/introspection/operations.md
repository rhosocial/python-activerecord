# 运维内省 (Operational Introspection)

[声明层](../introspection.md) 回答的是服务器**是什么**：它的表、列、索引，以及它们声明的内容。[列数据剖面](data-profiles.md) 回答的是行里**装着什么**。本页这六族回答第三个问题：服务器**一直在做什么**。

时态才是关键。声明是一个现在时的事实，在 schema 改变之前一直成立。运维答案是过去时的一个计数，覆盖服务器自己定义的一段窗口，并且只对那段窗口成立。这一族的大多数误读，都来自把过去时的数字读成现在时的属性：一个计数为零的索引变成"未使用"，而不是"自上次重置以来未使用"；一张没人扫过的表变成"冷的"，而不是"在这段窗口里没有被读过"。

| 方法 | 它问什么 |
|------|----------|
| `list_unused_indexes(schema=None)` | 在服务器记得的那段窗口里，哪些索引一次查询都没服务过 |
| `list_table_usage_stats(schema=None)` | 在那段窗口里，每张表被读、被写了多少次 |
| `list_runtime_metrics(schema=None)` | 服务器自己一直在做什么 |
| `list_index_usage_stats(schema=None)` | 每个索引被用了多少，而不只是有没有被用过 |
| `list_object_dependencies(object_name=None, schema=None)` | 哪个对象需要哪个对象，以及删掉一个会坏掉什么 |
| `get_ddl_statement(object_name, object_type=None, schema=None)` | 能把一个对象重建出来的那段文本 |

## 回答的时态

这里的清单型各族都返回一组窄记录，每条记录携带的是所测量对象的标识——对象是地址，指标是名字——外加一个 `extra` 映射，装着服务器在公共槽之外报告的额外内容。六族共享两条约定。缺席的槽是 `None`，表示未测量，永远不是零：一台不数某项东西的服务器，通过把那个槽留空来表达这一点，而不是报一个它从未数过的零。而窗口会跟着需要它的数字一起走，因为脱离窗口的计数不是事实。

## list_unused_indexes

一个索引的计数为零，它就是未使用。这是本层能给出的全部定义，而它比这个词听起来要弱：零意味着在服务器记得的那段窗口里没有扫描，而不是从来没有扫描。方法返回每个这类索引的地址——schema、表、索引——因为地址是所有能回答的服务器都能提供的；再多的数字落在 `extra` 里，含义由服务器自己说。

未使用索引是关于整个数据库的事实，而不是关于某一张表，所以这个调用不接受表名。缩小答案是调用方的事；一个被要求按表过滤的格式化方法，将不得不编出一个它的统计无法兑现的过滤条件，而编出来的过滤条件比如实报告答案更糟。

### 零是一个窗口，不是一生

窗口从上次重置开始——一次重启、一次统计重置、一次计数器刷写——这些事件的时刻由那个后端自己的文档说明。所以零说的是在那段时间里没有发生扫描，而一个已经服务了多年查询的索引，在重置后的第二天完全可能报零。答案里没有任何东西给这段窗口标上日期；除非连接另有说明，否则把这个数字当作相对于某个未言明的时刻。

缺席比零更弱。一个索引没有出现在清单里，不证明它被用过：它可能落在服务器能看到的统计之外，也可能低于清单所应用的门槛。把没出现当作没有证据，永远不要当作使用过的证据。

### 值得复查，不是可以删除

零让一个索引值得复查，而不是可以安全删除：它可能服务于被计数器记到别处的查询，可能在强制一条约束，也可能是唯一一个让某个罕见查询还能忍受的索引。这一族负责报告；决定属于一个知道这个索引是干什么用的读者。

## list_table_usage_stats

`list_table_usage_stats()` 用一个针对 schema 的查询读取每张表的计数器：顺序扫描与索引扫描、插入、更新、删除，外加把扫描次数变成表内占比的那个行数估计。用一个查询而不是每表一个查询，因为统计收集器的第一次读取远比后续读取贵，而每表的形式会诱使调用方一张表一张表地循环目录。

### 每一个计数都是"自某时以来"

每一个计数都是自统计上次重置以来，而服务器不跟踪的槽是 `None` 而不是零。零在这里是有含义的——窗口里什么都没发生——而它与"这台服务器不保存这种计数器"是不同的事实，这就是解析器把槽留空、而不是往上面写一个零的原因。

写侧的零和读侧的零支持不同的结论：前者说一张表被写但从未被读，后者说它被读但从未被写。这两个结论都经不起被读成"完全没有活动"。

## list_runtime_metrics

`list_runtime_metrics()` 返回的是对服务器的测量，而不是对某张表的测量：并发、吞吐、延迟、失败，凡是连接能作为一个有名字的数字报告的东西。它的每一项带一个名字和一个值，可选的 `kind`、`unit` 与 `description`，以及 `source`——这个数字所覆盖的窗口。

### 没有表名，这是有意的

这个语句接受 schema，但不接受表名，而这个省略是契约。运行时测量不附着在任何表上，所以表过滤会丢掉那些从来与表无关的行；一个不成立的过滤条件比没有过滤更糟，因为它看起来像一个答案。

除非服务器自己命名了 `kind`，否则它保持 `None`：从一个指标的名字去猜它是速率还是时长，会把服务器的统计变成这个库的解释。`source` 是含义所在。一个覆盖一分钟的吞吐数字和一个覆盖一天的吞吐数字都是真的，而没有那句说明哪一个的话，两个都没用。

## list_index_usage_stats

`list_index_usage_stats()` 是同一个主题更强的读法。未使用清单给出的是是或否，这一族给出背后的数字：`scans`、`rows_read`、`rows_fetched` 与 `size_bytes`，每一项只在服务器数它的时候出现。两族保持分开，而不是变成一个带 unused 标志的类型：问一个索引是否配得上它占的空间的读者要的是计数器，做一轮清理的读者要的是那份短清单。

### 用了多少，而不只是有没有用过

一次扫描的计数和一百万次扫描的计数描述的是不同的索引，而未使用清单分不出它们。计数器还回答清单回答不了的问题：一个只用过一次的索引不是未使用，但它仍然可能不值得它占的那些字节。服务器不数的槽是 `None`；零是一个测量。

## list_object_dependencies

`list_object_dependencies()` 把依赖图作为边返回：一个依赖方对象、它需要的对象、两者之间的关系，以及服务器声明了的话，删除时的行为。给出 `object_name` 会把答案收窄到那个对象的依赖方——也就是"我删掉这个会坏什么"的问题；省略它则返回整张图，更大也更慢。

### 方向是固定的

`dependent` 需要 `referenced`，方向没有商量余地：问"会坏什么"的读者问的是依赖方，而不是依赖。把这一对反过来，会让每个答案变成它的镜像，让一次安全的删除看起来危险，或者反过来。

### 边是引擎的记录

边是引擎记录的东西，而不是这个库从名字和调用点推断出来的。表上的视图、表上的索引、触发器用到的函数：每一条都是边，因为目录声明了它，而 `kind` 用引擎自己的词汇携带这层关系，因为没有标准词汇。

一个只记录更窄的边类型的引擎，是在如实回答它自己的目录；每一种边的含义，由那个后端自己的文档说明。

`action` 决定删除是否安全：服务器声明了的话就是 CASCADE、RESTRICT 或 SET NULL，没声明就是 `None`。没有 `action` 的图仍然说出什么依赖什么；它只是没有说出删除会做什么。

## get_ddl_statement

`get_ddl_statement()` 返回把一个对象重建出来的文本——"这个东西实际是以什么被创建的"的答案，而结构内省无法重建它：一个 check 表达式、一个生成列的表达式、一个存储参数、一个触发器体，都只存在于服务器保留的文本里。它总是关于一个对象，因为文本很大，而这个问题总是针对某个具体的东西问的。

### native 说明来源

`DDLStatement.native` 说明文本从哪里来：`True` 是服务器自己的取回结果，`False` 是这个库根据目录事实拼出来的组装结果，`None` 是服务器回答了但没说。这个区别不是形式上的。组装是一次重建，因此是有损的：它能重现列，也可能漏掉存储选项，所以一个要决定是否信任这段文本的调用方，必须知道手里是哪一种。

### None 不是不存在

`None` 意味着这段 DDL 无法被重现，而不是这个对象不存在。对象被找到了；服务器拒绝了，或者这个库无法组装它。把 `None` 读成"没有这张表"的调用方，会为一个真实存在且正常工作的对象报告说它缺失。不带文本的行会被跳过，而不是带着空的 `ddl` 返回，因为调用方要的是文本，而文本的缺席不是一个值。

在调用之前先查 `supports_ddl_extraction()`；当来源重要时，再查 `supports_ddl_extraction_native()`。一台服务器可能能回答、但不能原生回答，而一个需要原文的调用方，不能接受一次重建来替代它。

```python
ddl = backend.introspector.get_ddl_statement("orders", object_type="table")
if ddl is None:
    print("DDL could not be reproduced")
else:
    print(ddl.native, ddl.ddl)
```

## 代价

读计数器的那几族，在一个保存计数器的连接上是目录读取，在一个不保存的连接上是扫描。某一族属于哪种，取决于连接而不是族本身：未使用索引检测可能是对已保存统计的一次列举，也可能是一次总得有人付账的聚合，而同一个方法名覆盖两者。探针是调用方在付账之前弄清是哪一种的方式。

它们全部被缓存，而缓存的答案在这里比在声明层腐坏得更快。昨天缓存的 schema 大概还是那个 schema；昨天缓存的计数器描述的是一段从那以后一直在继续走的窗口。

回答不了一族的是一个为 `False` 的探针，不是一个空列表。空列表留给那种被问了、且确实没有东西可报告的问题；把两者分开，才能让一份报告说出它展示的是哪一种。
