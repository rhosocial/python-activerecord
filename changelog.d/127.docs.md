The user documentation's examples were brought back in line with the expression API this cycle introduced: `TableExpression` became `NamedRelationRef` over a relation object, `Column(...) == ...` became a typed-column comparison or an explicit `ComparisonPredicate`, `inline_literals=True` became `inline=True`, DDL statements take `Table` / `View` / `Index` / `Schema` / `Sequence` objects instead of name keywords, and the introspection pages describe the statement layer and the injectable `IntrospectionCache` rather than the retired hidden attribute. Every migrated page's code blocks were executed against the current API, and `scripts/verify_ddl_documentation.py` was removed because it kept a second copy of the same examples -- the copy is what rotted, not the check.

The command-line guides were brought under the same rule. The introspection type table now states what a `NAME` means for each type, in place of a single "table name required" column that was wrong for half of them; the backend-template page no longer keeps its own list of backend-specific types, which had two of the eight that exist, and points at each backend's own CLI page instead; and the examples that taught `--format json` now use the `-o json` the command actually accepts. The SQLite page also records the boundary the CLI draws around `backend.introspector.pragma`: `integrity_check`, `wal_checkpoint` and `journal_mode` are actions and state changes, not questions about what the database holds.
