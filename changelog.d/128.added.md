Add the introspection families that answer questions the declaration alone cannot: unused indexes, per-table usage counters, runtime metrics, index usage, object dependencies and DDL extraction, each with its `supports_*` predicate, its `format_*_query_statement` and its manager method pair, plus column data profiles (`ColumnDataProfile`, `ColumnValueFrequency`, `JoinCoverage`) that report which source the profile read through `ProfileSource`. Core gains `SequenceInfo` as the common minimum, and `IntrospectionTableInfo` gains `data_size_bytes` / `index_size_bytes` gated by `supports_table_storage_introspection` -- an engine whose storage is not row-plus-index shaped leaves them `None`, which is a legal answer rather than a gap. Composite primary keys gain identity: `identity_pk_fields()` reports which key fields the database fills, so a key may mix a generated member with a caller-supplied one, and `required_pk_columns()` names the caller's part for query analysis.
