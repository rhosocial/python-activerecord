A disjunction nested inside a conjunction keeps its brackets when a logical predicate renders, a SET DEFAULT value reaches the ALTER statement, a type modifier is judged where it is rendered rather than where it is declared, `UseColumnType` resolves `ColumnBase` at runtime, and escaping goes through the dialect instead of the base class.

`introspect columns` omitted a table's generated columns altogether. The question was `PRAGMA table_info`, which returns neither a generated column nor the `hidden` field that marks one, while the parser behind it had been written for `table_xinfo` all along -- so `is_generated` could never be true and the columns were missing from the list rather than mislabelled. SQLite's column question now asks `table_xinfo`; a virtual table's own hidden columns are still skipped, because they are the module's storage and not the table a caller reads, and a generated column's expression stays `None` because the pragma reports *that* a column is generated rather than what it is made of.

`pool.transaction()` no longer reports a failed rollback instead of the error that caused it: when the body raised and the rollback then failed (a transaction already ended by the failing statement, a lost connection), the `TransactionError` from the rollback replaced the original exception, so callers saw "No active transaction to rollback" for what was, in the observed case, a duplicate-key `IntegrityError`. The rollback failure is now logged and the original exception propagates, in both the sync and async pools.

A cancelled `acquire()` no longer keeps its semaphore permit. The connection-preparation code caught `Exception`, and `CancelledError` is a `BaseException`, so a caller that gave up while a backend was still connecting -- a readiness probe with a two-second budget, during a database restart -- leaked one permit per cancellation. The pool then reported `available=0, in_use=0` while every request waited out the acquire timeout, and never recovered on its own. The permit is now returned (and the half-prepared backend destroyed) on every exit that does not hand a connection to the caller.
