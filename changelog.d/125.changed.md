Make the expression layer collect parameters and the dialect layer decide: expression nodes no longer validate, normalise, or choose a spelling, and `format_*` decides both whether a clause can be expressed and how it is spelled. A capability probe now answers "can this dialect express this" while a parameter answers "which spelling was asked for". As part of this, `backend/dialect/protocols.py` became the `backend/dialect/protocols/` package with one protocol per module and two renames (`SchemaSupport` to `CreateSchemaSupport`/`DropSchemaSupport`/`NamespaceSupport`, `IndexSupport` to `CreateIndexSupport`/`DropIndexSupport`/`FulltextIndexSupport`/`IndexObjectSupport`); everything is re-exported from the package, so string references keep resolving. Clause pairs that were previously a single boolean, a tri-state `Optional[bool]`, or a sentinel value now have one parameter per spelling (`cycle`/`no_cycle`, `order`/`no_order`, `cache`/`no_cache`, `cascade`/`restrict`, `enforced`/`not_enforced`, `deferrable`/`not_deferrable`, `initially_deferred`/`initially_immediate`, `with_data`/`no_data`, `materialized`/`not_materialized`, `restart_identity`/`continue_identity`, `include_nulls`/`exclude_nulls`, `all_`/`distinct`, `wait`/`no_wait`), with "not specified" meaning neither is set and setting both raising `ValueError`. Backend implementations that read the old fields must be updated to read both parameters.
