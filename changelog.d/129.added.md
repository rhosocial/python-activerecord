Declare `__primary_key__ = None` a supported relation shape. A relation with no unique single-row key -- an insert-only audit log, an aggregate projection -- previously produced failures that read as accidents: `primary_key_columns()` returned `(None,)` rather than an empty tuple, and every identity operation raised `TypeError: attribute name must be string, not 'NoneType'` from `getattr`. The new `addressable()` classmethod is the single decision point for "can this row be addressed by primary key", and identity-based access -- `find_one(pk)`, `find_all([pk])`, `refresh()`, updating or deleting by key, and primary-key relation caching -- now raises `UnaddressableRecordError` naming the model and the operation and suggesting `where(...).one()`. Queries, ordering, grouping, aggregation, counting, `exists` and relations are unaffected, because none of them needs identity; conditions that are not bare key values (dicts, predicates, raw SQL) continue to work on a keyless model. `is_new_record` has no identity to inspect for such a model, so provenance decides: a row loaded from the database is not new, anything constructed in Python is. Post-insert primary-key retrieval is skipped rather than failing on an empty column list. Keyless-ness is orthogonal to read-only-ness in both directions, and this is independent of `ReadOnlyMixin` -- a materialized view model will use both.
