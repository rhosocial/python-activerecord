Let a `DDLSource` declare which kind of object it describes. The new `ObjectDeclaration` enum (`TABLE`, `VIEW`, `MATERIALIZED_VIEW`) is returned by `object_type()`, alongside `view_options()`, `view_definition()` and `view_dependencies()`. All four are declarations, never probes: no introspection happens, so model metadata stays resolvable at import time, and the DDL layer reads the value to choose a statement before applying the dialect's capability gates. `object_type()` defaults to `TABLE` and `view_definition()` accepts a `(dialect) -> expression` factory for the same reason column types do — annotations are evaluated before a dialect exists. Keeping this declarative is what leaves read-only-ness and keyless-ness independent: a model can be any combination of read-only, keyless and materialized-view, each declared where it belongs. `ObjectDeclaration` is deliberately distinct from `introspection.TableType`, which observes the catalog rather than declaring intent. A view can also be declared with no model behind it — `DDLSourceMixin` supplies 24 of the 28 protocol members, and the four identity methods (`table_name`, `schema_name`, `primary_key_columns`, `is_composite_pk`) are the whole cost. No dialect support is required to read these declarations, and no dialect implementation changed.
