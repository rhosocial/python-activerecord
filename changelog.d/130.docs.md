Document read-only and keyless models against the shipped API. The read-only guide previously taught users to hand-roll a mixin that raised `TypeError` from `save()`, `delete()` and `bulk_create()`, and none of its four use cases involved a materialized view; it now uses the built-in `ReadOnlyMixin`, covers every write path the framework actually gates, and states the boundary that matters -- the mixin prevents accidents, database credentials enforce policy, since `backend.expression` is publicly exported and a caller can still issue an UPDATE by hand. A new keyless-models guide documents `__primary_key__ = None` and `addressable()`, and a new views-as-queries guide explains why a view is a query rather than a model and when a database view is still the right answer. `ReadOnlyMixin` is registered in the mixins guide in both languages, and the runnable example is rewritten to exercise the real behaviour: eight demos covering the write gates, unaffected reads, a model that satisfies `IReadOnlyBehavior` yet stays writable, separate backends, the keyless surface, orthogonality, computed fields, and shared field definitions.
