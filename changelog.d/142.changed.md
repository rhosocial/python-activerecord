Add the neutral object-state API on the introspection manager: `get_table_state`, `get_partition_state`, `list_index_states`, `list_constraint_states`, `list_sequence_states`, `list_derived_objects`, `list_schemas` and `item_exists` answer with core dataclasses (`TableState`, `StorageOptionsState`, `PartitionState`, `PartitionBound`, `PartitionScheme`, `IndexState`, `ConstraintState`, `SequenceState`, `DerivedObjectState`, `ItemKind`) on both the sync and async introspector under the same names. `PartitionState.scheme=None` is the single neutral answer for "not partitioned" — `TableState.partitioning` is now a non-optional `PartitionState` (empty, with `scheme=None`, for an unpartitioned table), not `None`, so callers must not test it for `None`; `include_stats` defaults to `False` and, when left off, a backend must not run a statistics query at all rather than merely blank the values; a method a backend has not implemented raises `ProtocolNotImplementedError` naming the dialect, family and method instead of returning an empty list or `None`; and `item_exists` follows the three-case rule (the engine has no such objects → `False`, the query is implemented → answer, the objects exist but the query is not implemented → refuse). Split `IntrospectionSupport`/`AsyncIntrospectionSupport` and their mixins into four same-stem families — `StructureIntrospectionSupport`, `OperationalStatsIntrospectionSupport`, `DataProfileIntrospectionSupport` and `DdlExtractionIntrospectionSupport`, each with an async twin — with `IntrospectionMixin`/`AsyncIntrospectionMixin` becoming composition-only aggregates; a family counts as claimed only when at least one of its probes answers `True`.
