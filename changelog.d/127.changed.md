Capability predicates answer rather than raise when the version is unknown (an unadapted dialect now reports "not supported" instead of throwing `DialectNotAdaptedException`), every catalogue question became a statement class plus a dialect `format_*_query_statement` plus a public manager pair, and the `table_type` an `IntrospectionTableInfo` carries keeps the distinction `PRAGMA table_list` makes: on SQLite the storage tables behind an FTS or R-Tree virtual table are `SYSTEM_TABLE`, and the virtual table itself is `EXTERNAL`.

A `NAME` the type cannot use is now refused -- exit 2, the code that already means "there is no such question here" -- instead of being ignored. `introspect tables users` printed the whole catalogue while reading as though it had been narrowed, and `introspect views NAME` dropped the name altogether; the second now answers for that view and exits 1 when there is none. A *missing* required name keeps exit 1, the same code a missing connection argument gets, because the run never became a question.
