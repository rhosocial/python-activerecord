Fix three query defects that returned wrong results or malformed SQL instead of failing: `ActiveQuery.one()` / `AsyncActiveQuery.one()` now honour the accumulated join clause (they previously built their internal query from a bare table reference, so a joined `one()` silently returned unfiltered base-table rows); `not_in()` delegates to `in_()` and accepts the same three input shapes (a query object, an expression, or a list/tuple) instead of calling `tuple(values)` unconditionally; and `in_()` binds the dialect when wrapping a query object as a subquery, so `IN (SELECT ...)` no longer raises `ValueError: Subquery has no dialect bound`. `AsyncActiveQuery` gains the public `to_query_expression()` that `ActiveQuery` already had, restoring sync/async parity for subquery embedding and removing the duplicated expression construction in its `to_sql()`.
